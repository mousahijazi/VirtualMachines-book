Chapter 1: What is a Virtual Machine?

1.1 What is a real computer?

A physical computer is the device you touch with your hands. It consists of three basic layers:

ComponentDescriptionExample
HardwarePhysical partsCPU, Memory, Disk, Screen
Operating SystemThe software that manages the hardwareWindows, Linux, macOS
SoftwareThe applications you useChrome, VS Code, Games

1.2 What is a Virtual Machine?

A Virtual Machine (VM) is a complete computer — with a CPU, memory, hard disk, network, and operating system — but it is not a physical piece of hardware. It is a program running inside a real computer, behaving exactly as if it were an independent computer.

🏠 Everyday Analogy:
Imagine you live in a large house. Inside this house, you built a completely independent room — with its own door, key, and furniture. This room is part of the house, but it is isolated from it.

Technical Explanation: A virtual machine is an emulation program that creates an isolated environment simulating computer hardware. When the operating system runs inside the virtual machine, it thinks it is running on real hardware.

1.3 Basic Terminology

TermSimple Explanation
HostThe physical computer running the virtualization software
GuestThe operating system running inside the virtual machine
Virtual MachineThe software-emulated computer
HypervisorThe software that creates and manages virtual machines

A Hypervisor is like a "building manager" that distributes resources (electricity, water) to the different rooms. There are two types:

  • Type 1 (Bare-metal): Runs directly on the hardware — like VMware ESXi and Microsoft Hyper-V.
  • Type 2 (Hosted): Runs on top of an operating system — like Oracle VirtualBox and VMware Workstation.

1.4 Practical Example

Real Laptop (Host):

  • Windows 11
  • 24GB RAM
  • Intel Core i5 12th Gen

VM inside it (Guest):

  • Windows 11
  • 8GB RAM
  • 4 CPU cores
  • 80GB virtual disk

When the VM is powered on, 8GB of the 24GB is allocated to the virtual machine. The remaining 16GB is for the Host. This allocation is temporary — when the VM is closed, the memory is fully returned to the Host.

1.5 Is the VM a real computer?

QuestionAnswer
Does it have RAM?Yes — but virtual RAM allocated from the Host's memory
Does it have a CPU?Yes — virtual cores from the Host's CPU
Does it have a Hard Disk?Yes — but it is a virtual disk (a file on the Host's disk)
Does it have a Network Card?Yes — a virtual adapter emulated in software
Does it have an Operating System?Yes — a complete operating system

🧠 Test Your Understanding

Q1: If I have a real Windows and a virtual Windows, which one is called the Host?

The real Windows is the Host because it is the physical device running the virtualization software.

Q2: Is the VM's RAM real or fake?

It's real memory allocated from the Host, but it's "virtual" from the VM's perspective.

Q3: What is the difference between Host and Guest?

Host = The physical computer. Guest = The operating system running inside the VM.

Chapter 2: How does the Virtual Machine work internally?

2.1 Virtualization

Virtualization is the technology that allows running more than one operating system on the same hardware. The Hypervisor distributes resources among the virtual systems.

2.2 CPU Virtualization

The real CPU contains cores. When you give a VM "4 CPU cores", you allow it to use 4 cores from the Host's CPU. The Hypervisor schedules the usage of these cores.

Note: If the processor has 8 cores, and you gave the VM 4, it does not mean the Host will be left with only a 4-core processor. It means the VM is authorized to use up to 4 cores when needed.

2.3 Intel VT-x / AMD-V

To achieve good performance, modern processors need Hardware Virtualization — a built-in feature in the CPU that accelerates virtual machines:

  • Intel VT-x: Intel's technology
  • AMD-V: AMD's technology

If this feature is not enabled in the BIOS/UEFI, virtual machines will run extremely slowly or won't run at all.

2.4 Virtual Disk

The Virtual Disk is a large file on the Host's disk that contains all the VM's data. There are several types:

  • VDI: The default format in VirtualBox
  • VHD/VHDX: From Microsoft (Hyper-V)
  • VMDK: From VMware

Two allocation modes:

  • Dynamically Allocated: Grows gradually as needed (best for beginners)
  • Fixed Size: Fully allocated from the start (faster, but takes space immediately)

2.5 Resource Allocation Table

ResourcePhysical DeviceWhat we give the VMImpact

2.6 Does running a VM make the computer slower?

Yes, temporarily. When the VM is running: a portion of RAM is reserved, some cores are busy, and the GPU may be slower.

When does the computer become slow?

  • If you give the VM more than 60% of the Host's memory.
  • If you run a heavy VM on a device with low memory.
  • If the disk is an HDD rather than an SSD.
⚠️ Warning: Do not run a heavy VM on a device with less than 8GB of RAM — the experience will be painful.

🧠 Test Your Understanding

Q1: Why do we need to enable Intel VT-x?

Because it significantly accelerates VM performance through direct hardware support.

Q2: What is the difference between Dynamic and Fixed Disk?

Dynamic grows gradually as needed, while Fixed allocates the full space from the beginning.

Chapter 4: Creating your first Virtual Machine from Scratch

4.1 Detailed Steps

1. Open VirtualBox — the main interface will appear.

2. Click New — the creation wizard begins.

3. Enter the Name — Example: Windows 11 VM.

4. Select the Type — Type: Microsoft Windows, Version: Windows 11 (64-bit).

5. Allocate Memory (RAM) — Minimum 4GB, ideally 8GB.

6. Allocate Processor (CPU) — 2 to 4 cores.

7. Create a Virtual Hard Disk:

  • Select Create a Virtual Hard Disk Now
  • Type: VDI (VirtualBox Disk Image)
  • Size: 80GB with Dynamic Allocation

8. Mount the ISO File — From Settings → Storage, select the ISO file.

9. Click Start — the installation begins.

10. Follow the installation steps as if you were installing it on a real computer.

11. Install Guest Additions — From Devices → Insert Guest Additions CD Image.

12. Restart — After installation, your VM is ready.

4.2 Difference Between Programs on Host and Guest

If I delete Chrome from the VM, is the Host affected?No — they are independent
Are files shared?Only with Shared Folders enabled
Does the VM consume Host resources?Yes — RAM, CPU, Disk

Chapter 6: Snapshots and Backups

6.1 What is a Snapshot?

A Snapshot is a saved image of the VM's state at a specific moment in time. Like "saving a game" — you can revert to it later.

🎮 Analogy: Imagine you are playing a difficult game. You reach an advanced level, and you save. Then you lose. What do you do? You load the previous save. A Snapshot is exactly this — but for an entire virtual machine.

Practical Example:

  1. You created a clean Windows VM.
  2. You took a Snapshot named Clean Windows.
  3. You installed 20 programs and the system crashed.
  4. You clicked Restore → The system reverted to the clean state in seconds!

6.2 Difference Between Snapshot and Backup

FeatureSnapshotBackup
What does it do?Temporarily saves VM stateFully copies the VM
Where is it stored?Next to the VM filesIn a separate location
PurposeQuick rollbackDisaster recovery
DurationShort-termLong-term
Protects against disk failure?NoYes
🚨 Common Mistake: Believing that a Snapshot replaces a Backup. If the hard disk fails, the Snapshot is lost with it.

6.3 Difference Between Snapshot, Clone, Export, and Import

RestoreReverting to a previous Snapshot
CloneA complete, independent copy of the VM
BackupA full copy stored externally

🧠 Test Your Understanding

Q1: What is the difference between NAT and Bridged?

NAT puts the VM behind the Host — it cannot be accessed from outside. Bridged makes the VM an independent device with its own IP on the local network.

Q2: When should you use Internal Network?

When you want a completely isolated network connecting VM1 and VM2 only.

8.2 Changing Internal IP ≠ Changing Public IP

Changing the internal IP of the VM does not change the Public IP that websites see. To change your internet exit address, you need:

  • VPN (Virtual Private Network)
  • Proxy
  • A different Wi-Fi network
  • A different Router
Note: This chapter is for understanding only — not an invitation to anonymize yourself or bypass the law.

9.2 VM Escape

VM Escape is a vulnerability that allows a program inside the VM to break out and gain control of the Host. These vulnerabilities are rare but they exist (e.g., CVE-2025-22226 in VMware/Virtualization platforms).

⚠️ Attention: This doesn't mean VMs are insecure. They provide very strong isolation, but they are not a 100% magical impenetrable wall.

Chapter 15: Tor and Dark Web — Awareness

15.1 What is Tor?

Tor (The Onion Router) is an onion-routing network that allows relatively anonymous internet browsing.

15.2 How does Onion Routing work?

  1. The user selects a path through 3 Nodes.
  2. Data is encrypted in 3 layers (like an onion).
  3. Each node peels off one layer only.
  4. Only the final node (Exit Node) sees the final destination.

15.3 Difference between Surface Web, Deep Web, and Dark Web

LayerDescriptionExample
Surface WebIndexed by search enginesGoogle, YouTube
Deep WebPassword-protected contentYour email, bank account
Dark WebHidden networks.onion websites
Important: The Dark Web isn't entirely criminal. It is also used by journalists, activists, and people seeking privacy.

Chapter 17: Practical Lab Project

"Build Your First Virtual Lab"

Goal: Create a safe lab to learn Linux, networking, and programming.

Components:

  • Host: Windows
  • VM1: Ubuntu
  • VM2: Ubuntu (Optional)

Steps:

  1. Create VM1 → Install Ubuntu
  2. Create VM2 → Install Ubuntu
  3. Configure NAT for VM1 (for Internet access)
  4. Create a Host-only Network between VM1 and VM2
  5. Install Software: Node.js, Git, VS Code (via SSH)
  6. Take a Snapshot named Base Setup
  7. Test connection: ping between VM1 and VM2
  8. Break the network: Try disconnecting the adapter
  9. Restore Snapshot: Return to the clean state
  10. Safely delete the VM

Chapter 18: Common Beginner Mistakes

Mistakes to Avoid

  • ❌ Giving a VM full access to Host files unnecessarily
  • ❌ Using Shared Folders with sensitive files
  • ❌ Using Bridged Networking without understanding it
  • ❌ Passing untrusted USB devices to the VM
  • ❌ Believing a VM offers 100% protection
  • ❌ Believing a VPN offers 100% anonymity
  • ❌ Believing Tor offers 100% anonymity
  • ❌ Running suspicious files with antivirus disabled
  • ❌ Not updating VirtualBox
  • ❌ Not updating the Guest OS
  • ❌ Saving sensitive passwords in a testing environment
  • ❌ Confusing Snapshots with Backups

Chapter 19: Frequently Asked Questions (FAQ)

Can a virus escape from a VM?
Very rarely — only through a VM Escape vulnerability.
Does a VM change my IP?
It changes your Private IP — not your Public IP.
Does a VM change my device identity?
It changes some hardware info — but not everything.
Does a VM make me anonymous?
No — isolation ≠ anonymity.
Can I run multiple VMs?
Yes — provided you have enough resources.
Can I run a VM inside a VM?
Yes — Nested Virtualization. But it is slower.
Do games work?
Some do — but performance might be poor.
Can I use a VM for programming?
Yes — excellent for Linux and backend development.
Do I need a VM for Nexmart?
Not necessarily right now — but useful for the future.
Is VirtualBox free?
Yes — free and open-source.
What's the difference between a VM and Sandbox?
A VM is permanent — Sandbox is temporary.
What's the difference between a VM and a VPN?
VM = a complete computer. VPN = an encrypted network tunnel.
Is the Dark Web all about crime?
No — but it does contain illegal activity.
Is using Tor legal?
Yes — but using it to commit crimes is illegal.
Is a Snapshot a Backup?
No — Snapshots are just for quick rollbacks.
Can I move a VM to another computer?
Yes — via Export/Import.
