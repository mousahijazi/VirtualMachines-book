الفصل 1: ما هو الكمبيوتر الافتراضي؟

1.1 ما هو الكمبيوتر الحقيقي؟

الكمبيوتر الحقيقي (Physical Computer) هو الجهاز الذي تلمسه بيدك. يتكون من ثلاث طبقات أساسية:

المكونالوصفمثال
Hardware (العتاد)الأجزاء الماديةالمعالج، الذاكرة، القرص، الشاشة
Operating Systemالبرنامج الذي يدير العتادWindows، Linux، macOS
Software (البرمجيات)التطبيقات التي تستخدمهاChrome، VS Code، الألعاب

1.2 ما هو Virtual Machine؟

Virtual Machine (الجهاز الافتراضي) هو كمبيوتر كامل — بمعالج وذاكرة وقرص صلب وشبكة ونظام تشغيل — لكنه ليس قطعة مادية. إنه برنامج يعمل داخل كمبيوتر حقيقي، ويتصرف تمامًا كما لو كان كمبيوترًا مستقلًا.

🏠 تشبيه من الحياة اليومية:
تخيل أنك تعيش في بيت كبير. داخل هذا البيت، بنيت غرفة مستقلة تمامًا — لها بابها الخاص، ومفتاحها الخاص، وأثاثها الخاص. هذه الغرفة جزء من البيت، لكنها معزولة عنه.

التفسير التقني: الجهاز الافتراضي هو برنامج محاكاة (Emulation) ينشئ بيئة معزولة تحاكي عتاد الكمبيوتر. عندما يعمل نظام التشغيل داخل الجهاز الافتراضي، يظن أنه يعمل على جهاز حقيقي.

1.3 المصطلحات الأساسية

المصطلحالترجمةالشرح البسيط
Hostالمضيفالكمبيوتر الحقيقي الذي يشغل البرنامج
Guestالضيفنظام التشغيل الذي يعمل داخل الجهاز الافتراضي
Virtual Machineالجهاز الافتراضيالكمبيوتر المُحاكى بالبرمجيات
Hypervisorمدير الأجهزة الافتراضيةالبرنامج الذي يخلق الأجهزة الافتراضية ويديرها

Hypervisor هو مثل "مدير المبنى" الذي يوزع الموارد (الكهرباء، الماء) على الغرف المختلفة. هناك نوعان:

  • Type 1 (Bare-metal): يعمل مباشرة على العتاد — مثل VMware ESXi وMicrosoft Hyper-V.
  • Type 2 (Hosted): يعمل فوق نظام تشغيل — مثل Oracle VirtualBox وVMware Workstation.

1.4 مثال عملي

  • Windows 11
  • 24GB RAM
  • Intel Core i5 12th Gen

1.5 هل الـVM جهاز حقيقي؟

السؤالالإجابة

هل لها CPU؟نعم — أنوية افتراضية من معالج الـHost

🧠 اختبر فهمك

س1: إذا كان لدي Windows حقيقي وWindows افتراضي، أيهما يسمى Host؟

الـWindows الحقيقي هو الـHost لأنه الجهاز الفعلي الذي يشغل البرنامج.

س2: هل RAM الـVM حقيقية أم وهمية؟

ذاكرة حقيقية مقتطعة من الـHost، لكنها "افتراضية" من منظور الـVM.

س3: ما الفرق بين Host وGuest؟

Host = الكمبيوتر الفعلي. Guest = نظام التشغيل الذي يعمل داخل VM.

الفصل 2: كيف يعمل الكمبيوتر الافتراضي من الداخل؟

2.1 Virtualization (الافتراضية)

Virtualization هي التقنية التي تسمح بتشغيل أكثر من نظام تشغيل على نفس العتاد. الـHypervisor يوزع الموارد بين الأنظمة الافتراضية.

2.2 CPU Virtualization

المعالج الحقيقي يحتوي على أنوية (Cores). عندما تعطي الـVM "4 CPU cores"، أنت تسمح لها باستخدام 4 أنوية من معالج الـHost. الـHypervisor يجدول استخدام هذه الأنوية.

ملاحظة: لو كان المعالج 8 أنوية، وأعطيت الـVM 4، لا يعني أن الـHost سيصبح بمعالج 4 أنوية. بل يعني أن الـVM مصرّح لها باستخدام حتى 4 أنوية عند الحاجة.

2.3 Intel VT-x / AMD-V

لتحقيق أداء جيد، تحتاج المعالجات الحديثة إلى Hardware Virtualization — ميزة مدمجة في المعالج تسرّع عمل الأجهزة الافتراضية:

  • Intel VT-x: تقنية إنتل
  • AMD-V: تقنية AMD

إذا لم تُفعّل هذه الميزة في BIOS/UEFI، ستعمل الأجهزة الافتراضية ببطء شديد أو لن تعمل أصلًا.

2.4 Virtual Disk

الـVirtual Disk هو ملف كبير على قرص الـHost يحتوي على كل بيانات الـVM. هناك أنواع:

  • VDI: النوع الافتراضي في VirtualBox
  • VHD/VHDX: من Microsoft (Hyper-V)
  • VMDK: من VMware

نمطان:

  • Dynamically Allocated: يكبر تدريجيًا (الأفضل للمبتدئ)
  • Fixed Size: يُحجز كاملًا منذ البداية (أسرع، لكن مساحة فورية)

2.6 هل تشغيل VM يجعل الجهاز أبطأ؟

نعم، مؤقتًا. عندما يكون الـVM قيد التشغيل: جزء من الـRAM محجوز، جزء من الأنوية مشغولة، والـGPU قد يكون أبطأ.

متى يصبح الجهاز بطيئًا؟

  • إذا أعطيت الـVM أكثر من 60% من ذاكرة الـHost.
  • إذا شغلت VM ثقيلة على جهاز بذاكرة قليلة.
  • إذا كان القرص HDD وليس SSD.
⚠️ تحذير: لا تشغّل VM ثقيلة على جهاز بذاكرة أقل من 8GB — التجربة ستصبح مؤلمة.

🧠 اختبر فهمك

س1: لماذا نحتاج تفعيل Intel VT-x؟

لأنه يسرّع عمل الـVM بشكل كبير عبر دعم العتاد المباشر.

س2: ما الفرق بين Dynamic وFixed Disk؟

Dynamic يكبر تدريجيًا، Fixed يُحجز كاملًا من البداية.

الفصل 3: VirtualBox — بوابتك إلى العالم الافتراضي

3.1 ما هو VirtualBox؟

Oracle VirtualBox هو برنامج افتراضي مجاني ومفتوح المصدر من شركة Oracle. يسمح بإنشاء وتشغيل أجهزة افتراضية على جهازك.

3.2 لماذا VirtualBox؟

الميزةالتفصيل
مجاني تمامًامفتوح المصدر تحت رخصة GPL
متعدد المنصاتWindows، Linux، macOS
سهل للمبتدئينواجهة رسومية بسيطة
مجتمع ضخمدعم ومصادر لا نهائية
يدعم أنظمة كثيرةWindows، Linux، BSD، Solaris

3.3 التحميل من المصدر الرسمي

الرابط الرسمي الوحيد الموثوق:

https://www.virtualbox.org/wiki/Downloads

⚠️ تحذير أمني: لا تنزّل VirtualBox من مواقع عشوائية. استخدم الرابط الرسمي فقط.

3.4 التثبيت على Windows

  1. اذهب إلى الرابط الرسمي أعلاه
  2. اختر Windows hosts لتنزيل ملف .exe
  3. شغّل ملف التثبيت
  4. اتبع التعليمات (Next → Next → Install)
  5. بعد التثبيت، ستظهر أيقونة VirtualBox في قائمة Start
💡 نصيحة: نزّل أيضًا VirtualBox Extension Pack من نفس الصفحة لدعم USB 2.0/3.0.

3.5 مكونات VirtualBox

  • VirtualBox Manager: الواجهة الرسومية
  • VBoxManage: أداة سطر أوامر للأتمتة
  • VBoxSDL: واجهة بسيطة
  • Extension Pack: حزمة إضافات اختيارية

الفصل 4: إنشاء أول جهاز افتراضي من الصفر

4.1 الخطوات التفصيلية

1. افتح VirtualBox — ستظهر الواجهة الرئيسية.

2. اضغط New (جديد) — يبدأ معالج الإنشاء.

3. أدخل الاسم — مثلًا: Windows 11 VM.

4. اختر النوع — Type: Microsoft Windows، Version: Windows 11 (64-bit).

5. حدد الذاكرة (RAM) — 4GB كحد أدنى، 8GB مثالي.

6. حدد المعالج (CPU) — 2 إلى 4 أنوية.

7. أنشئ قرصًا افتراضيًا:

  • اختر Create a Virtual Hard Disk Now
  • النوع: VDI (VirtualBox Disk Image)
  • الحجم: 80GB مع Dynamic Allocation

8. اربط ملف ISO — من Settings → Storage، اختر ملف ISO.

9. اضغط Start — يبدأ التثبيت.

10. اتبع خطوات التثبيت كأنك تثبته على جهاز حقيقي.

11. ثبّت Guest Additions — من Devices → Insert Guest Additions CD Image.

12. أعد التشغيل — بعد التثبيت، الـVM جاهز.

السؤالالإجابة

الفصل 6: Snapshots والنسخ الاحتياطي

6.1 ما هو Snapshot؟

Snapshot (لقطة) هي صورة لحالة الـVM في لحظة معينة. مثل "حفظ اللعبة" — يمكنك العودة إليها لاحقًا.

🎮 تشبيه: تخيل أنك تلعب لعبة صعبة. وصلت إلى مستوى متقدم، وحفظت. بعد ذلك خسرت. ماذا تفعل؟ تُحمّل الحفظ السابق. الـSnapshot هي بالضبط هذا — لكن لجهاز افتراضي كامل.

مثال عملي:

  1. أنشأت Windows VM نظيفة.
  2. أخذت Snapshot باسم Clean Windows.
  3. ثبّتت 20 برنامجًا وخرب النظام.
  4. عملت Restore → عاد النظام إلى الحالة النظيفة في ثوانٍ!

🧠 اختبر فهمك

س1: ما الفرق بين NAT وBridged؟

NAT يجعل الـVM خلف الـHost — لا يمكن الوصول إليها من الخارج. Bridged يجعل الـVM جهازًا مستقلًا بIP خاص.

س2: متى تستخدم Internal Network؟

عندما تريد شبكة معزولة تمامًا بين VM1 وVM2 فقط.

8.2 تغيير IP الداخلي ≠ تغيير Public IP

تغيير IP الداخلي للـVM لا يغيّر الـPublic IP الذي تراه المواقع. لتغيير عنوان الخروج للإنترنت:

  • VPN (شبكة افتراضية خاصة)
  • Proxy (وسيط)
  • شبكة Wi-Fi مختلفة
  • Router مختلف
ملاحظة: هذا الفصل للفهم فقط — ليس دعوة للتخفي أو تجاوز القانون.

9.2 VM Escape

VM Escape هو ثغرة تسمح لبرنامج داخل الـVM بالخروج والسيطرة على الـHost. هذه الثغرات نادرة لكنها موجودة (مثل CVE-2025-22226 في VirtualBox).

⚠️ تنبيه: هذا لا يعني أن VM غير آمنة. توفر عزلًا قويًا جدًا، لكنها ليست جدارًا سحريًا بنسبة 100%.

الفصل 15: Tor وDark Web — توعية

15.1 ما هو Tor؟

Tor (The Onion Router) هو شبكة توجيه بصلية تسمح بتصفح الإنترنت بشكل مجهول نسبيًا.

15.2 كيف يعمل Onion Routing؟

  1. يختار المستخدم مسارًا من 3 عقد (Nodes).
  2. يتم تشفير البيانات في 3 طبقات (مثل البصلة).
  3. كل عقدة تفك طبقة واحدة فقط.
  4. العقدة الأخيرة (Exit Node) ترى الوجهة النهائية.

15.3 الفرق بين Surface Web وDeep Web وDark Web

الطبقةالوصفمثال

الفصل 17: مشروع المختبر العملي

"ابنِ أول مختبر افتراضي لك"

الهدف: إنشاء مختبر آمن لتعلم Linux والشبكات والبرمجة.

المكونات:

  • Host: Windows
  • VM1: Ubuntu
  • VM2: Ubuntu (اختياري)

الخطوات:

  1. إنشاء VM1 → تثبيت Ubuntu
  2. إنشاء VM2 → تثبيت Ubuntu
  3. ضبط NAT للـVM1 (للإنترنت)
  4. إنشاء Host-only Network بين VM1 وVM2
  5. تثبيت البرامج: Node.js، Git، VS Code (عبر SSH)
  6. أخذ Snapshot باسم Base Setup
  7. اختبار الاتصال: ping بين VM1 وVM2
  8. إيقاف الشبكة: جرّب قطع الاتصال
  9. استعادة Snapshot: ارجع للحالة النظيفة
  10. حذف VM بأمان
✅ هذا المشروع تعليمي وقانوني بالكامل.

الفصل 18: الأخطاء الشائعة للمبتدئين

أخطاء لا ترتكبها

  • ❌ إعطاء VM وصولًا كاملًا لملفات Host دون حاجة
  • ❌ استخدام Shared Folder مع ملفات حساسة
  • ❌ استخدام Bridged Networking بدون فهمه
  • ❌ توصيل USB غير موثوق بالـVM
  • ❌ الاعتقاد أن VM = حماية 100%
  • ❌ الاعتقاد أن VPN = مجهول 100%
  • ❌ الاعتقاد أن Tor = مجهول 100%
  • ❌ تشغيل ملفات مشبوهة مع تعطيل الحماية
  • ❌ عدم تحديث VirtualBox
  • ❌ عدم تحديث Guest OS
  • ❌ حفظ كلمات مرور حساسة في بيئة اختبار
  • ❌ الخلط بين Snapshot وBackup

الفصل 19: الأسئلة الشائعة (FAQ)

هل يمكن للفيروس الخروج من VM؟
نادرًا جدًا — فقط عبر ثغرة VM Escape.
هل VM تغير IP؟
تغيّر Private IP — لا Public IP.
هل VM تغير الجهاز؟
تغيّر بعض المعلومات — لكن ليس كلها.
هل VM تجعلني مجهولًا؟
لا — العزل ≠ الإخفاء.
هل يمكن تشغيل أكثر من VM؟
نعم — بشرط كفاية الموارد.
هل يمكن VM داخل VM؟
نعم — Nested Virtualization. لكنها أبطأ.
هل الألعاب تعمل؟
بعضها — قد يكون الأداء ضعيفًا.
هل يمكن استخدام VM للبرمجة؟
نعم — ممتازة لـLinux والتطوير.
هل أحتاج VM لـNexmart؟
ليس بالضرورة الآن — مفيدة مستقبلًا.
هل VirtualBox مجاني؟
نعم — مجاني ومفتوح المصدر.
ما الفرق بين VM وSandbox؟
VM دائمة — Sandbox مؤقتة.
ما الفرق بين VM وVPN؟
VM = كمبيوتر كامل. VPN = نفق شبكة.
هل Dark Web كله جرائم؟
لا — لكنه يحتوي نشاطًا غير قانوني.
هل استخدام Tor قانوني؟
نعم — لكن استخدامه في جريمة غير قانوني.
هل Snapshot Backup؟
لا — Snapshot للتراجع السريع فقط.
هل يمكن نقل VM إلى جهاز آخر؟
نعم — عبر Export/Import.
